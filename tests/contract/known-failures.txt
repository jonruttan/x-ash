# known-failures.txt -- the specs this bundle is known to fail.
#
# One "UNIT: TEST" per line, matching the runner's own `FAIL:` lines verbatim.
# Blank lines and #-comments are ignored.
#
# BY NAME, NOT BY COUNT.  A budget of "2 failures" is satisfied by fixing one
# and breaking another, which is the exact event a ratchet exists to catch.
# Names catch it; a number cannot.
#
# THE LIST MAY ONLY SHRINK.  tests/spec-gate.sh is red when a failure appears
# that is not here, AND when a line here starts passing.
#
# READ THIS BEFORE BELIEVING THE GATE
# ===================================
#
# This list describes x-ash on x-engine-c **v0.1.3**.  lang.xon declares
# x-lang v0.7.0, and v0.7.0 pins x-engine-c **v0.1.2** -- on which this bundle
# does not merely fail, it is dead at load: 80 of 82 red.  v0.1.2's
# x_prim_make_token_base segfaults on the first character of any input, and an
# isolated tokenizer base is the one thing this bundle cannot do without.
#
# So CI is red until x-lang cuts a release pinning v0.1.3 and lang.xon's
# (requires-release ...) moves to it.  That is the honest state, and recording
# 80 failures instead would be worse in every way: it would enshrine a
# platform bug this bundle did not cause as debt this bundle owns, it would
# have to be torn up the day the pin moves, and it would hide the two failures
# that are actually ash's.
#
# The two below ARE ash's, and they are what this file is for.
